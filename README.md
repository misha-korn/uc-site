# Сайт учебного центра (ДПО и профобучение)

Готовый сайт образовательной организации дополнительного профессионального образования:
охрана труда, пожарная безопасность, первая помощь, электробезопасность, рабочие профессии.
Сделан под требования **Приказа Рособрнадзора от 04.08.2023 № 1493** в действующей редакции
(изменения приказами № 1353 от 03.07.2025 и № 920 от 30.04.2026, действует с 01.09.2026).

- Главная, каталог программ с фильтром по направлениям, страница каждой программы, контакты.
- Форма заявки с согласием на обработку персональных данных, защитой от спама и уведомлениями в Telegram / на почту.
- Раздел **«Сведения об образовательной организации»** — все 14 подразделов с микроразметкой `itemprop`.
- Версия для слабовидящих (размер шрифта, цветовые схемы, отключение изображений).
- Панель управления на русском языке (`/admin/`): заказчик сам меняет программы, цены, документы и сведения.
- Политика обработки ПДн, согласие, `robots.txt`, `sitemap.xml`.

> В репозитории — **демо-данные** вымышленной организации «Учебный центр «Профресурс»» (г. Самара).
> Перед запуском для реального заказчика их нужно заменить (см. «Чек-лист перед запуском»).

**Технологии:** Python 3.12+, Django 5.2 (ASGI, uvicorn), PostgreSQL (на сервере) / SQLite (на компьютере),
WhiteNoise, собственный CSS и JavaScript без внешних CDN и шрифтов Google.

## 1. Структура проекта

```
uc-site/
```

## 2. Быстрый старт на Windows

### Шаг 1. Установите Python
1. Скачайте Python **3.12 или новее** с https://www.python.org/downloads/
2. При установке **обязательно отметьте галочку «Add python.exe to PATH»**.
3. Проверьте: откройте «Командную строку» (Win+R → `cmd` → Enter) и введите `python --version`.

### Шаг 2. Скачайте проект
Распакуйте архив проекта, например, в `C:\Projects\uc-site`
(или `git clone ...`, если установлен [Git](https://git-scm.com/download/win)).

> Путь лучше без пробелов и русских букв.

### Шаг 3. Установка — один раз
Откройте папку проекта и **дважды щёлкните `scripts\setup.bat`** (или в командной строке:
`cd C:\Projects\uc-site` и `scripts\setup.bat`). Скрипт сам:
1. создаст виртуальное окружение `.venv`;
2. установит зависимости из `requirements.txt`;
3. создаст файл настроек `.env` из `.env.example` со случайным `SECRET_KEY`;
4. создаст базу данных (`migrate`) и загрузит демо-данные (`seed_demo`);
5. попросит придумать логин и пароль для панели управления (`createsuperuser`).

### Шаг 4. Запуск — каждый раз
Дважды щёлкните **`scripts\run.bat`** и откройте в браузере:
- сайт — http://127.0.0.1:8000/
- панель управления — http://127.0.0.1:8000/admin/

Остановить сервер — `Ctrl+C` в чёрном окне. Код меняется «на лету»: сохранили файл — обновили страницу.
`scripts\run.bat django` — запуск встроенным сервером Django вместо uvicorn.

<details>
<summary>То же самое вручную (если .bat не запускается)</summary>

```bat
cd C:\Projects\uc-site
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python -m uvicorn config.asgi:application --reload
```
Если PowerShell пишет «выполнение сценариев отключено» — используйте `cmd`, а не PowerShell,
или выполните один раз: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
</details>

## 3. Быстрый старт на Linux / macOS

```bash
./scripts/setup.sh     # один раз: .venv, зависимости, .env, база, демо-данные, суперпользователь
./scripts/run.sh       # запуск: http://127.0.0.1:8000/
```
Для демо-PDF с кириллицей нужен шрифт DejaVu: `sudo apt install fonts-dejavu-core`
(на macOS/Windows укажите путь к любому TTF с кириллицей в `PDF_FONT_PATH` в `.env`).

Через Docker (PostgreSQL + сайт + nginx одной командой):
```bash
cp .env.example .env       # поменяйте POSTGRES_PASSWORD и SECRET_KEY
docker compose up -d --build
docker compose exec web python manage.py seed_demo          # демо-данные (по желанию)
docker compose exec web python manage.py createsuperuser
```
Сайт будет на http://localhost/ (порт — `HTTP_PORT` в `.env`).

## 4. Раздел «Сведения» и как его заполнять в панели

### 4.1. Что требует приказ № 1493
Раздел `/sveden/` доступен с главной и из основного меню, на **каждой** странице раздела — меню всех подразделов,
у каждой страницы — дата обновления сведений, данные размечены атрибутами `itemprop` (их проверяют роботы
Рособрнадзора), документы — PDF с текстовым слоем, подписанные **простой электронной подписью**.

| Адрес | Подраздел | Что заполнять в панели `/admin/` |
|---|---|---|
| `/sveden/common/` | Основные сведения | **Основные сведения об организации** (одна запись), **Учредители**, **Места осуществления образовательной деятельности** |
| `/sveden/struct/` | Структура и органы управления | **Структура и органы управления** — у каждого подразделения поле «Положение о подразделении (файл)», ссылка выводится прямо в строке таблицы |
| `/sveden/document/` | Документы | **Документы** с разделом «Документы»: устав, правила, локальные акты, отчёт о самообследовании, предписания |
| `/sveden/education/` | Образование | **Программы обучения** (файлы программы, учебного плана, РПД, календарного графика, методички), **Документы** (языки, численность), **Текстовые сведения** |
| `/sveden/eduStandarts/` | Образовательные стандарты и требования | **Документы** и **Текстовые сведения** (для ДПО — указание, что ФГОС не применяются, ссылки на профстандарты) |
| `/sveden/managers/` | Руководство | **Руководство** (директор и заместители) |
| `/sveden/employees/` | Педагогический состав | **Педагогический состав** (+ привязка к программам) |
| `/sveden/objects/` | МТО и доступная среда | **Материально-техническое обеспечение** (кабинеты, площадки, библиотека, спорт), **Текстовые сведения** (доступная среда, ЭОР, общежитие) |
| `/sveden/paid_edu/` | Платные образовательные услуги | **Документы** (порядок оказания, образец договора, приказ о стоимости); цены — из программ |
| `/sveden/budget/` | Финансово-хозяйственная деятельность | **Текстовые сведения** (объём деятельности, поступление и расходование средств; год — поле с itemprop `finYear`) + **Документы** (план ФХД) |
| `/sveden/vacant/` | Вакантные места | **Вакантные места** — по каждой программе |
| `/sveden/grants/` | Стипендии и меры поддержки | **Текстовые сведения** / **Документы** |
| `/sveden/inter/` | Международное сотрудничество | **Текстовые сведения**: каждый договор — поле с itemprop `internationalDog`, значение «Страна; Организация; Реквизиты договора». Нет записей — выводится «Отсутствует» |
| `/sveden/catering/` | Организация питания | **Текстовые сведения**: объект питания — поле с itemprop `meals`, значение «Название; Адрес; Приспособленность для ОВЗ»; плюс условия охраны здоровья |

Если сведений нет (например, нет общежития или международных договоров) — **не удаляйте** строку,
а впишите «Отсутствует» / «Не предусмотрено»: по требованиям элемент с `itemprop` должен быть на странице.

### 4.2. Как работать в панели
1. Откройте `https://ваш-сайт/admin/` и войдите под своим логином.
2. Слева — разделы «Сайт» (направления, программы, заявки) и «Сведения об образовательной организации».
3. Чтобы изменить запись — щёлкните по ней, поправьте поля, нажмите **«Сохранить»**.
   Дата обновления на сайте меняется автоматически.
4. Порядок вывода — поле **«Порядок»** (меньше число — выше).

### 4.3. Как загрузить документ с электронной подписью
1. Подготовьте PDF **с текстовым слоем** (не фото/скан без распознавания — иначе нарушение п. 22–26).
2. Подпишите документ простой ЭП (например, отметка о подписании внутри PDF: ФИО, должность, дата,
   или подпись в Adobe Acrobat / КриптоПро PDF).
3. В панели: **Документы → Добавить документ**:
   - **Раздел** — на какой странице выводить (например, «Документы»);
   - **itemprop** — выберите из подсказок (например, `ustavDocLink` для устава) — это служебная метка для робота Рособрнадзора;
   - **Название** — понятное: «Устав АНО ДПО …» (подпись ссылки должна объяснять, что за файл);
   - **Файл** — загрузите PDF (до 20 МБ) **или** укажите **Ссылку**, если документ лежит на другом сайте;
   - номер и дата документа; отметьте **«Подписан ЭП»**, впишите **«Кем подписан»** и **дату подписи**;
   - **«Опубликован»** — снимите галочку, чтобы временно скрыть документ.
4. Сохраните и откройте страницу раздела на сайте — проверьте, что ссылка открывает файл.

Файлы образовательной программы (сама программа, учебный план, РПД, график, методические материалы)
загружаются прямо в карточку **программы обучения** — они автоматически появятся в подразделе «Образование».

### 4.4. Где itemprop и как проверить
`itemprop` уже прописаны в шаблонах `templates/sveden/*.html` — программировать ничего не нужно, только заполнять данные.
Для документов и «Текстовых сведений» метка берётся из поля **itemprop** записи: не меняйте его у демо-записей,
просто замените текст и файлы. Проверить разметку: откройте страницу → правый клик → «Просмотреть код» →
поиск `itemprop`. Полный список меток — `research/REQUIREMENTS_1493.md`.

## 5. Заявки и уведомления

Заявки с сайта сохраняются в панели: **Сайт → Заявки**. Меняйте статус («Новая» → «В работе» → «Обработана»),
пишите служебные заметки. Вместе с заявкой сохраняются версия согласия на обработку ПДн, дата согласия и IP.

Защита от спама: скрытое поле-ловушка + не более 5 заявок с одного IP за 10 минут
(`LEAD_RATE_LIMIT`, `LEAD_RATE_WINDOW`). Счётчик хранится в памяти процесса, поэтому сайт по умолчанию
запускается одним процессом uvicorn (`WEB_CONCURRENCY=1`). За nginx включите `USE_X_FORWARDED_FOR=1`
(в Docker и systemd-службе это уже сделано), без nginx — оставьте `0`.

Уведомление о новой заявке приходит **без персональных данных** — только «Новая заявка #N» и ссылка в панель
(так безопаснее: ПДн не уходят в мессенджер).

**Удаление данных.** Клиент отозвал согласие → в списке заявок отметьте её и выберите действие
«Удалить выбранные заявки» или «Удалить персональные данные (обезличить)». Заявки старше 1 года (срок из Политики)
удаляет команда `python manage.py purge_leads` — на сервере её запускает cron/таймер раз в сутки (DEPLOY.md,
раздел «Персональные данные: автоудаление заявок»). Проверить без изменений: `python manage.py purge_leads --dry-run`.

### Telegram
1. В Telegram найдите **@BotFather** → `/newbot` → придумайте имя → получите **токен** вида `123456:ABC-DEF...`.
2. Напишите своему боту любое сообщение (или добавьте бота в рабочую группу и напишите там).
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}` —
   это **ID чата** (для групп — отрицательное число, например `-1001234567890`).
4. В `.env`:
   ```ini
   TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
   TELEGRAM_CHAT_ID=-1001234567890
   SITE_URL=https://ваш-сайт.ru
   ```
5. Перезапустите сайт и отправьте тестовую заявку.

### E-mail
Пример для Яндекс.Почты (нужен **пароль приложения**: Яндекс ID → Безопасность → Пароли приложений):
```ini
EMAIL_HOST=smtp.yandex.ru
EMAIL_PORT=465
EMAIL_USE_SSL=1
EMAIL_HOST_USER=info@ваш-домен.ru
EMAIL_HOST_PASSWORD=пароль-приложения
DEFAULT_FROM_EMAIL=info@ваш-домен.ru
LEADS_EMAIL_TO=manager@ваш-домен.ru,director@ваш-домен.ru
```
Mail.ru: `smtp.mail.ru`, 465, SSL. Если `EMAIL_HOST` пуст — письма не отправляются (на компьютере печатаются в консоль).

## 6. Настройки (.env)

Все настройки — в файле `.env` в корне проекта (шаблон с пояснениями — `.env.example`). Главное:

| Переменная | На компьютере | На сервере |
|---|---|---|
| `SECRET_KEY` | любая | длинная случайная, **секретная** |
| `DEBUG` | `1` | **`0`** |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | `ваш-сайт.ru,www.ваш-сайт.ru` |
| `CSRF_TRUSTED_ORIGINS` | — | `https://ваш-сайт.ru,https://www.ваш-сайт.ru` |
| `DATABASE_URL` | пусто (SQLite) | `postgres://user:pass@localhost:5432/uc_site` |
| `SITE_URL` | `http://localhost:8000` | `https://ваш-сайт.ru` |
| `SITE_DEMO` | `0` (по умолчанию); `1` — только демо-стенд (плашка «демо», запрет индексации) | **`0`** |
| `SECURE_SSL_REDIRECT` | `0` | `1` (после настройки HTTPS) |
| `TELEGRAM_*`, `EMAIL_*` | по желанию | см. раздел 5 |
| `USE_X_FORWARDED_FOR` | `0` | `1` (только за своим nginx) |
| `SERVE_MEDIA` | авто | `0` за nginx, `1` на хостинге без nginx |
| `PDF_FONT_PATH` | Windows: `C:\Windows\Fonts\arial.ttf` | DejaVu (по умолчанию) |
| `DEMO_ADMIN_PASSWORD` | по желанию — создаст `admin` в `seed_demo` (слабый пароль при `SITE_DEMO=0` не принимается) | **не задавать** |
| `LEAD_RETENTION_DAYS` / `LEAD_SPAM_RETENTION_DAYS` | `365` / `30` | как в Политике ПДн (`purge_leads`) |
| `CSP_REPORT_ONLY` | `0` | `0` (`1` — только для отладки внешнего сервиса) |
| `SECURE_HSTS_PRELOAD` | — | `0` (включать только осознанно) |
| `MEDIA_ROOT` | пусто = `media/` | пусто или свой путь |

После изменения `.env` перезапустите сайт.

## 7. Статическая демо-копия

Для показа заказчику по ссылке без сервера (GitHub Pages, Netlify, любой хостинг, даже просто папка на диске):

```bash
python scripts/export_static.py --out dist
# или из другой базы:
python scripts/export_static.py --out dist --database-url sqlite:////tmp/demo.sqlite3
# база и загруженные PDF из временных папок:
python scripts/export_static.py --out dist --database-url sqlite:////tmp/demo.sqlite3 --media-root /tmp/demo-media
```
Windows: `scripts\export_static.bat`.

Скрипт отрисует все страницы (главная, каталог и каждое направление, все программы, контакты, «Сведения» и все
подразделы, политика, согласие, страница 404), перепишет ссылки в относительные (`../sveden/common/index.html`),
скопирует CSS/JS/картинки и PDF из `media/`, а формы переведёт в демо-режим (не отправляются).
Ссылка на панель `/admin/` из копии убирается. В конце проверяются все ссылки — при битых скрипт
выводит список и завершается с кодом 1. Откройте `dist/index.html` в браузере.

Публикация на GitHub Pages: залейте содержимое `dist/` в ветку `gh-pages` (или включите Pages для папки)
— файлы `.nojekyll` и `robots.txt` (запрет индексации демо) создаются автоматически.

Тесты переписывания ссылок: `python -m unittest scripts/test_export_static.py -v`.

## 8. Развёртывание на сервере

Подробная пошаговая инструкция — **[DEPLOY.md](DEPLOY.md)**:
- **VPS + Docker Compose** (PostgreSQL 16 + сайт + nginx) — проще всего;
- **VPS без Docker** — systemd-служба `deploy/systemd/uc-site.service` + nginx `deploy/nginx/uc-site.conf` + certbot;
- **обычный хостинг с Python** (Beget, Timeweb) — через Passenger/WSGI;
- **бэкапы** — `scripts/backup_db.sh` (база + media, хранение 14 дней) и таймер systemd для ежедневного запуска.

Автоматические проверки на GitHub (`.github/workflows/ci.yml`) при каждом push: `check`, отсутствие
несозданных миграций, применение миграций на PostgreSQL, тесты, загрузка демо-данных, экспорт статической
копии без битых ссылок, `check --deploy`, синтаксис shell-скриптов, сборка Docker-образа и healthcheck.

## 10. Полезные команды и частые проблемы

```bash
python manage.py runserver                 # простой запуск для разработки
python manage.py createsuperuser           # новый администратор
python manage.py changepassword ЛОГИН      # сменить пароль
python manage.py seed_demo --reset         # пересоздать демо-данные (УДАЛЯЕТ текущие данные!)
                                           # при SITE_DEMO=0 нужен ещё --force
python manage.py test                      # тесты
python manage.py check --deploy            # проверка боевых настроек
```
(На Windows вместо `python` внутри проекта используйте `.venv\Scripts\python`.)

| Проблема | Решение |
|---|---|
| `python` не найден | Переустановите Python с галочкой «Add to PATH» или используйте `py` |
| `No module named django` | Не активировано окружение: `.venv\Scripts\activate` (Linux: `source .venv/bin/activate`) |
| На странице нет стилей при `DEBUG=0` | Выполните `python manage.py collectstatic` |
| Кракозябры в консоли Windows | Выполните `chcp 65001` или используйте Windows Terminal |
| Демо-PDF без русских букв | Укажите путь к TTF-шрифту с кириллицей в `PDF_FONT_PATH` (Windows: `C:\Windows\Fonts\arial.ttf`) |
| Ошибка `SECRET_KEY` при `DEBUG=0` | Задайте `SECRET_KEY` в `.env` |
| Другое | Смотрите текст ошибки в окне, где запущен сервер; на сервере — DEPLOY.md, «Если что-то не работает» |
